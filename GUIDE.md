# PR Review — как этим пользоваться
Простая инструкция для человека: что это, как поставить, и как ревьюить код —
свои изменения, ветку и настоящие пул-реквесты с GitHub.
---
## Что это вообще
Обычный просмотр diff в терминале показывает изменения, но в нём неудобно
оставлять замечания, и он ничего не умеет передавать дальше. Эта утилита
поднимает **локальную веб-страницу в стиле GitHub Pull Request** — прямо на
твоём компьютере, на `http://127.0.0.1:...`.
Ты открываешь её в браузере и делаешь всё как на GitHub:
- видишь файлы, подсветку синтаксиса и номера строк;
- выделяешь мышкой диапазон строк и пишешь комментарий;
- вставляешь скриншот прямо в комментарий (`Ctrl+V`);
- переходишь к определению символа (как «Go to definition»);
- нажимаешь **Request changes / Approve** — и ревью **уходит в чат с AI**,
  который сразу начинает править код.
То есть: ты ревьюишь глазами, а рутинную правку делает нейросеть.
---
## 1. Первый запуск (5 минут)
### Что нужно
1. **Node.js 20+** — <https://nodejs.org> (кнопка LTS).
2. **Git** — обычно уже стоит.
3. Для ревью **пул-реквестов с GitHub** ещё нужен **GitHub CLI** (`gh`).
   Об этом отдельный раздел ниже — для обычных ревью он не нужен.
### Установка
```bash
git clone <этот-репозиторий> pr-review-mcp
cd pr-review-mcp
npm install
```
`npm install` сам проверит, есть ли `gh`. Если его нет — просто напишет
подсказку, как поставить; **ничего не сломается**.
### Запуск
```bash
# ревью того, что ты ещё не закоммитил (рабочая папка)
npm run review -- "C:\путь\к\проекту" 5454
```
В консоли появится адрес, открой его в браузере:
```
http://127.0.0.1:5454/
```
Всё. Страница живёт, пока ты её не закроешь (или пока не остановишь процесс).

## 2. Что можно ревьюить
Утилита умеет смотреть на разные «наборы изменений». Выбираешь одним флагом
`--mode`:
| Что хочешь посмотреть | Команда |
| --- | --- |
| Только незакоммиченное | `npm run review -- . --mode uncommitted` |
| Всю текущую ветку против базовой | `npm run review -- .` *(это режим по умолчанию)* |
| Конкретный диапазон коммитов | `npm run review -- . --mode range --base origin/dev --head my-branch` |
| Отдельные коммиты | `npm run review -- . --mode commits` |
| Всю историю ветки | `npm run review -- . --mode all` |
| **Настоящий PR с GitHub** | `npm run review -- . --mode pr --pr 42` |
Плюс можно указать порт (`5454`) и открыть браузер автоматически (`--open`).

## 3. Как ревьюить: пошагово
Страница разбита на три части: слева **(1) дерево файлов**, в центре
**(2) сам diff**, справа **(3) панель ревью** с комментариями.
### Оставить комментарий
1. Наведи мышь на **строку** — в жёлобах слева появится `+`.
2. Зажми `+` на первой строке и **протяни** до последней — выделится диапазон.
3. Откроется поле для текста. Пиши замечание.
4. Хочешь приложить скриншот — просто **вставь** его (`Ctrl+V`) или перетащи файл.
5. **Add comment**.
### Отметить просмотренным
У каждого файла справа сверху есть галочка **Viewed**. Нажал — файл
сворачивается и больше не мешает. Прогресс виден в шапке
(«12 / 30 viewed»).
Шапка файла **прилипает к верху** при прокрутке (как на GitHub), так что
после просмотра длинного файла не нужно листать обратно наверх, чтобы нажать
**Viewed**.
> Повторное ревью после правок — это **новое** ревью: если код изменился, все
> отметки Viewed начинаются заново. Если ничего не менялось, отметки
> сохраняются.
### Полный путь и меню файла
- **Наведи на путь** — появится крупная подсказка с полным путём: длинный путь
  обрезается в строке, а подсказка показывает его целиком, разделяя папку и имя.
- **Иконка копирования** рядом с путём — копирует путь одним кликом.
- **Три точки (⋯)** справа в шапке файла — второстепенные действия:
  - **View file** — открыть файл в отдельной вкладке;
  - **Add file comment** — комментарий ко всему файлу;
  - **Expand all** — раскрыть скрытые куски, и только если что-то реально
    скрыто.
  Кнопка видна всегда, без наведения.
### Вкладка «View file»
Файл открывается **ровно таким, какой он в проекте**: обычный текст, без
подсветки синтаксиса и без зелёных полос изменений. Есть только номера строк и
«+» в жёлобе, чтобы можно было оставлять комментарии.
### Настройки (шестерёнка)
Настройки **запоминаются на этом устройстве** и переживают новое ревью,
изменение кода и перезапуск страницы (они хранятся на сервере, а не в браузере:
страница каждый раз открывается на новом порту).
- **Diff layout** — унифицированный или side-by-side (как в IDE).
- **Hide viewed files** — прятать уже просмотренные.
- **Symbol links** — кликабельные имена (переход к определению).
- **Тема** — тёмная/светлая (кнопка ◐ в шапке).
- **Tree indent** — ширина отступов в дереве.
- **Collapse files over** — большие файлы не раскрываются сразу.
