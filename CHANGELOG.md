# Changelog
Все заметные изменения проекта собраны здесь.
Формат основан на [Keep a Changelog](https://keepachangelog.com/ru/1.1.0/),
версии — по [Semantic Versioning](https://semver.org/lang/ru/).
## [1.3.0] - 2026-11-25
Команда `pr <ссылка>` для ревью любого пул-реквеста, автообновление и понятные
сообщения об ошибках вместо «git не установлен».

### Добавлено
- Команда `pr https://github.com/owner/repo/pull/123` (или `pr owner/repo#123`,
  или `pr 123`): открывает страницу ревью PR, печатает локальный адрес и даёт
  отправить ревью обратно в GitHub. Работает из любого чекаута: PR из другого
  репозитория тянется по его URL, без добавления remote.
- `npm run update` и `npm run update -- --check`: обновление до новой версии из
  npm, без git и без сборки.
- Один тихий вывод «доступна новая версия» при запуске, не чаще раза в сутки;
  отключается `PR_REVIEW_NO_UPDATE_CHECK=1`.

### Исправлено
- Сообщение «git executable not found» появлялось, когда на самом деле не было
  папки проекта: Node отдаёт одинаковый код ошибки. Теперь отдельно говорится,
  что папки нет, что папка не является git-репозиторием (и что открыть), а
  также что репозиторий пуст или ветка не выбрана.
- Обновление не откатывает на более старую версию, если реестр отстал от
  чекаута.

## [1.2.0] - 2026-11-24
Публикация ревью в GitHub прямо со страницы, дерево файлов с отступом 4 px и
расширение Visual Studio с кнопкой на стандартной панели.

### Добавлено
- **Publish to GitHub** в диалоге Submit: вердикт и инлайн-комментарии уходят в
  настоящий pull request через `gh`, без веб-интерфейса GitHub.
- Панель `PR Review` в Visual Studio открывает ревью текущей ветки в отдельной
  вкладке; пакет ставится из `editors/visualstudio/bin/Release/net48`.
- Браузерный тест раскладки: 655/1000/1440 px, обе раскладки diff, без бокового
  скролла и обрезки, дерево скрывается на узкой вкладке.

### Изменено
- Для ревью pull request по умолчанию выбран вердикт **Comment**: заметки больше
  не блокируют PR случайно. Локальная отправка осталась отдельной кнопкой
  **Submit locally**.
- PR сравнивается от merge-base, поэтому ушедшая вперёд база не показывает свои
  коммиты как удаления PR, а номера строк совпадают с GitHub.
- `Tree indent (px)` по умолчанию 4 вместо 16.
- Комментарии в коде убраны, повторяющиеся литералы вынесены в константы
  (`PR.HTTP`, `PR.EVENT`, `PR.KEY`).

### Исправлено
- Повторный клик публикации не отправляет те же комментарии второй раз; отметка
  хранится на сервере и переживает переоткрытие ревью.
- Ревью привязано к просмотренному коммиту (`commit_id`), поэтому push во время
  ревью не делает все комментарии устаревшими.
- Устаревшие комментарии и всё сверх лимита GitHub в 100 инлайн-комментариев
  переносятся в тело ревью вместо ошибки 422.
- При отказе GitHub диалог остаётся открытым с текстом и комментариями, причина
  видна, кнопку можно нажать снова.

## [1.1.2] - 2026-11-19
Публикация ревью на GitHub и три исправления, найденные на реальном ревью.
### Добавлено
- `publish_review`: отправляет локально написанное ревью в пул-реквест на GitHub
  как настоящее review — вердикт **Approve** / **Request changes** / **Comment**
  плюс инлайн-комментарии с привязкой к файлу и строке. Комментарий без строки
  уходит в текст ревью, потому что GitHub привязывает только к строкам.
### Исправлено
- Ревью, открытое не из чата, больше не уходит в чужую сессию: страница не
  наследует идентификатор сессии из окружения, владельцем становится только та
  сессия, которую передал MCP-вызов.
- Для режимов `range`, `branch`, `commits` и `all` содержимое файлов читается из
  ревьюемого коммита, а не с диска. Раньше посторонние правки в рабочей копии
  подменяли файл: из диффа пропадали строки, а подсветка не совпадала с текстом.
- Файл больше не обрезается посреди диффа: убраны `content-visibility: auto` и
  `contain: paint`, из-за которых браузер дорисовывал только часть секции и
  хвост файла исчезал без кнопки раскрытия.
## [1.1.1] — 2026-11-19
Два исправления интерфейса, найденные на реальном ревью.
### Исправлено
- Меню файла (⋯) больше не перекрывается заголовком следующего файла: пока меню
  открыто, секция поднимается над соседями.
- Во вкладке **View file** длинные строки переносятся, а не растягивают страницу
  вбок: таблица больше не подстраивается под самую длинную строку и номера строк
  не уезжают за экран.
- Настройка «Collapse files over N» теперь считает размер файла, а не только
  изменённые строки. Снимок на несколько тысяч строк сворачивается, даже если
  правок в нём меньше порога; подпись говорит, что именно превышено.
## [1.1.0] — 2026-11-18
Отправка ревью одним окном, выбор ветки и починка подсветки.
### Добавлено
- Одна кнопка **Submit review** вместо двух: в окне выбирается вердикт
  — **Request changes** или **Approve** — и пишется заметка.
- **Approve** тоже уходит агенту: он получает сообщение, что работа принята,
  и заметку, если она есть, но код по своей инициативе не переписывает.
- Отправку можно выключить прямо в окне: ревью сохранится в
  `review.json` / `review.md`, а ход в чате не стартует.
- Выбор ветки на вкладке Commits: список коммитов любой ветки, а не только
  той, что открыта на ревью.
- `npm run bundle:hljs` пересобирает бандл подсветки из установленного
  highlight.js, со списком языков в одном месте.
### Исправлено
- Подсветка больше не пропадает на файлах, где встречается имя вроде
  `constructor` или `toString`: раньше такой файл оставался белым и не
  догружался до конца.
- Go, Java, Rust, Kotlin, Ruby, PHP и ещё несколько языков подсвечиваются,
  а не показываются простым текстом.
- Файл, добавленный в индекс и потом ещё раз изменённый, больше не попадает
  в ревью дважды — из-за этого последняя строка выглядела задублированной.
- «Expand all» раскрывает файл целиком и убирает синюю кнопку раскрытия.
- Автоотправку нельзя случайно включить через API, если она выключена для
  ревью: проверка теперь на сервере, а не только в браузере.
## [1.0.0] — 2026-11-18
Первый стабильный релиз.
### Добавлено
- Локальная страница ревью в стиле GitHub Pull Request: дерево файлов,
  подсветка синтаксиса, номера строк, прогресс просмотра.
- Пять локальных режимов: незакоммиченные изменения, ветка, диапазон,
  выбранные коммиты и вся история.
- Ревью пул-реквестов GitHub через `gh`: head скачивается в служебную ссылку,
  ветка и рабочие файлы не затрагиваются.
- Инлайн-комментарии с выделением диапазона строк и вставкой скриншотов.
- Статусы комментариев: resolve и unresolve, для человека и для агента.
- Переход к определению символа и список использований.
- Переключение раскладки diff, тёмная и светлая темы, настройка отступов дерева.
- Настройки хранятся на устройстве и переживают новое ревью и перезапуск.
- MCP-сервер с инструментами `start_review`, `await_review`, `get_review`,
  `list_review_scope`, `resolve_comments`, `close_review`,
  `list_pull_requests`.
- Отправка готового ревью в сессию агента одним нажатием.
- Автоотправка работает только с OpenCode; с другими ассистентами ревью
  сохраняется в `review.json` и `review.md`, и агент читает его оттуда.
- Интеграции для VS Code, Visual Studio 2022, JetBrains, Neovim, Sublime Text,
  Emacs, Zed и Helix.
- Автоматическая проверка GitHub CLI при установке и команда `npm run gh:install`.
- Артефакты ревью пишутся во временную папку системы, проект остаётся чистым.
### Исправлено
- Файл с пробелом в имени больше не разбивается на два пути при разборе diff.
- Добавленные файлы отображаются в дереве зелёным, а не пропадают.
- Лишняя пустая строка в конце добавленного файла убрана.
- Список коммитов показывает только коммиты ветки, а не всю историю репозитория.
- Повторное ревью после правок больше не наследует старые отметки просмотра.
- Комментарий на неизменённом файле открывается, а не падает с ошибкой.
- Заголовок файла закрепляется при прокрутке длинного файла.
- Настройки больше не сбрасываются при смене страницы ревью.
